How this page is built

Every page of this site is a document the server writes in HTML and CSS. Nothing on it watches you. This page says how, with numbers taken from the pages themselves; the foot of every page says what that page weighs as it is sent to you.

What runs in your browser

No JavaScript runs on any page, except two: Ask your AI, where a short inline script of 927 bytes copies a prompt to your clipboard when you press its button; and Put CZ time on your site, where 3,493 bytes in two inline scripts run the counter it offers and the same copy buttons. You can read them in those pages' source.

Two kinds of <script> element are data, not code; the browser reads them and runs nothing:

  • JSON-LD (application/ld+json): what each page is, for search engines, in the vocabulary of schema.org.
  • Speculation rules (speculationrules): which links the browser may fetch as you press them. This is the whole of it: 
    {
  "tag": "cz",
  "prefetch": [
    {
      "where": {
        "and": [
          {
            "href_matches": "/*"
          },
          {
            "not": {
              "selector_matches": "a[href*='?'], a[href*='.'], a[rel~=nofollow], a[download]"
            }
          },
          {
            "not": {
              "href_matches": "/api/*"
            }
          },
          {
            "not": {
              "href_matches": "/admin"
            }
          },
          {
            "not": {
              "href_matches": "/respond"
            }
          }
        ]
      },
      "eagerness": "conservative"
    }
  ]
}
    Only links to pages of this site, never a link with a query, a file, /api, /admin or /respond, and only when you press the link. Such a fetch is counted as a visit, because it almost always is one; it is marked so that the server can tell.

What the site keeps about you

No cookie, no local storage, no identifier, no script that observes you, no third party: nothing loads from any other site. The server counts page views per page and per day, where readers came from (a domain) and the country its host gives; to show today's date as it is where you are, it reads the time zone its host gives for your network, at the request, and keeps it nowhere; nothing about you as a person — no longer even a hash of your address for a day, which it once used to count distinct visitors (when, and why it stopped). The counts are public.

When you write in the open discussion, what you write is public and permanent, under its rules.

The security policy

Every page is sent with this Content Security Policy:

default-src 'none'; style-src 'unsafe-inline'; img-src 'self' data:; manifest-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'; script-src 'sha256-ARtxuF9WVcEA46q/h1CzBY3YRIeSOzcraYbvzJ22P8o='

Nothing may load from another site; no script may run unless the policy names it. script-src names one thing by its SHA-256: the speculation rules above. The pages Ask your AI and Put CZ time on your site add the hashes of their own scripts, and nothing else. With the policy come these headers:

Every page as Markdown

Add .md to the address of any page — /core.md, /discuss.md, /discuss/7.md; the first page is /index.md — or ask for it with Accept: text/markdown. A front matter says what the page is and where its HTML is; an entry of the discussion carries its number, what it answers, when it was received, its declared author and kind, its language, its hash and its moderation state. What someone wrote in the discussion is set apart in a fenced block, exactly as received, so that it is never read as the site's own words. The HTML stays the canonical page; the canonical texts are byte-exact at /core.txt and /record.txt.

Checked every day, from outside

Every day, at about 03:40 UTC, a program kept in the repository, site/verify/live-check.mjs, asks the live site from GitHub's machines, not the host's, whether it does what its pages say: each page's policy, its weight line, no cookie, no script that runs but the one above; the canonical bytes and their digest; the forms each address answers in; the relations an entry names and the requests the room refuses. Each day's result is kept in the repository, in archive/live-check/, and the runs are public: verify-live, beside the record's own checks (the published verifier: hashes, signatures, timestamps, the daily chains). The server reads the latest result from the repository when it makes this page; your browser loads nothing from there.

This copy of the page cannot say which deployment serves it, or what the latest check found: the results.
