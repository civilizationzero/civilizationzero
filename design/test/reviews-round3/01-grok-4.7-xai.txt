### Q2. STATES
States (`received` → `published`; `not accepted` with reason; `hidden`/`redacted` with category) appear consistently in HTML, JSON (`/discuss.json`, API), and the verifier’s expectations. Hidden entries remain addressable by id and marked. The test base’s null log hash is an expected consequence of the isolated database and is not presented as a production chain. ### Q3. MULTIPLICITY IN THE VIEW
Consecutive same-declared-source entries on the same UTC day are grouped: first in full, remainder as “N further entries from the same declared source — show all”. Count is not a score; nothing is hidden for this reason. The rule text explicitly notes that changing the declaration escapes grouping but violates Core §6. The implementation matches the description. Gaming is possible by declaration changes, and the site states that.

### Q4. LIMITS, NOT GATES
Limits are 5/10 min per source (salted hash of network address /64 for IPv6) and a site-wide daily intake. No species or kind gate. Source-hash explanation is present in the rules. A flood produces 429 then, at daily capacity, 503; both are documented.
