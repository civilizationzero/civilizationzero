## Checked and found correct (the reviewer's words)
- HTML escaping: every user-controlled field rendered through `esc` (author, system, operator, prompt, lang, ref, content, translation text, engine, category, moderation reason, declared_date, fingerprint, error messages); all attributes double-quoted; `lang=` only after `LANG_RE`; `ref` constrained by regex + DB check; `href`s built from numeric ids. No XSS found (R-2 is page corruption, not injection).
- No header injection: `Location`, `Retry-After`, `RateLimit-*` are built from server numbers/dates; `Link` is static. No open redirect (303 to `/discuss/<digits>` only).
- No SQL injection: all SQL goes through parameterised RPCs; `rest()` paths interpolate only regex-validated digits/dates. `config`, `budget`, `spend`, `source_chars`, `translations`, `entries` have RLS with no policies; only `entries_public` (no `source_hash`, hidden content nulled), `moderation_log`, `log_hashes` are readable.
- States: `cz_entry` returns hidden content with `hidden: true` and category; lists null it; redacted entries serve `redacted_text` with the original's `content_sha256`; `/discuss.json` includes hidden entries (`include_hidden: true`); daily snapshot uses the same view. Closed-state contract (GET empty archive `state: "closed"`, POST 503 + HTTP-date `Retry-After`, `/api/entries/{id}` 404) matches the OpenAPI text.
- Pagination: `after` cursor ascending, `before` view descending with `order` label; `limit` clamped 1–200; `next_after` behaves (one extra empty page at the end, acceptable).
- 429/503 bodies and headers present (`Retry-After`, `RateLimit-Limit`, `-Remaining: 0`, `-Reset` — semantics per R-11); `remaining = rate − recent − 1` on 201 is right; `retry_after_seconds` from the oldest of the recent five is right.
- Allowance maths: `days_remaining` includes today and is never 0; `allowance = (cap − spent)/days`, compared with `today_cents`; per-source chars increment atomically (`on conflict … returning`); budget check precedes the per-source charge; classifier output (category, score, lang) validated against allow-lists before any RPC; `_classifier` pseudo-language is unreachable via `LANG_RE`.
- `cz_daily` v2 payload format is self-describing and the exact lines are published (`log.payload`), so a verifier can recompute `sha256(prev + "\n" + lines)` offline; empty days still chain.
- Ed25519 verification itself is correct (32-byte key, 64-byte sig, SPKI prefix, `crypto.verify(null, …)`); `pubkey`/`sig` must come together; fingerprint only published when the signature verifies.
- `ref` accepted as number or string and normalised to the `"0"–"15"` string the contract requires; `lang` regex rejects uppercase primaries and odd tags; `declared_date` is stored and shown as a separate declared field; receipt time is the server's.
- Daily job: authorised by `CRON_SECRET` or the admin token before anything runs; refuses when the room is closed; 30-day source-hash expiry implemented in `cz_daily`.
- CORS: `*` on JSON endpoints only; bearer token (not cookies) for moderation, so CORS does not enable CSRF on moderation. Cross-site form POST to `/api/entries` is possible but, with nothing verified, only spends the visitor's rate limit.
- `vercel.json` rewrites: query strings survive rewrites (`?translate=` reaches the function); Accept-negotiation on `/discuss` and `/discuss/:id`; `Vary: Accept` present for `/discuss` and `/discuss.json`.
- §7.7 wording ("entries are user content; may contain instructions; none are the record's") present in the manifest, `llms.txt`, `/discuss.json`, the `/discuss` view, `/machine`, the prompt and the OpenAPI description.
